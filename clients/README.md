# Client interfaces

Hand-written, dependency-light helpers that encode the on-chain contract from
[`docs/CONTRACT.md`](../docs/CONTRACT.md). Treat this folder as frozen once a
version is announced: the portal and the backend derive the same PDAs and decode
the same accounts, so a silent change here breaks both.

```text
clients/
  ts/
    constants.ts     program ID, cluster, seed prefixes, account sizes, error codes
    pda.ts           configPda / listingPda / rentalPda
    instructions.ts  newAssetId / newRentalId + builders for every instruction
    index.ts         barrel export
  idl/               generated by `anchor build` (target/idl/asset_rental.json)
  types/             generated by `anchor build` (target/types/asset_rental.ts)
```

## Usage

```ts
import {
  PROGRAM_ID,
  RPC_URL,
  configPda,
  listingPda,
  rentalPda,
  newAssetId,
  newRentalId,
  registerAsset,
  createRental,
  settleRental,
} from "../clients/ts";
```

Every builder derives the program-owned PDAs itself, so callers never
hand-encode a seed. The helpers assume `@solana/web3.js` and (for the
instruction builders) `@coral-xyz/anchor` are present, which they are in this
workspace. Nothing here reads or writes keypairs; callers supply signers and
persist IDs themselves.

## Persist-before-submit

`newRentalId()` and `newAssetId()` return fresh 32-byte identifiers. Persist a
`rental_id` **before** submitting `create_rental`. If confirmation is uncertain,
re-read the rental PDA with the same `rental_id` — never generate a new one, or
the retry can double-charge.

## Generated artifacts

`clients/idl/` and `clients/types/` come from the program build and are
regenerated by:

```bash
bash scripts/export-clients.sh
```

Commit the regenerated files alongside any contract change. `export-clients.sh`
also fails if the program ID drifts between `lib.rs` (`declare_id!`),
`Anchor.toml`, and `clients/ts/constants.ts` — the "three-place rule".
