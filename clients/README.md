# Client interfaces

One implementation of the on-chain contract, imported by the portal, the backend,
and the acceptance tests. Treat this folder as frozen once a version is announced:
a silent change here changes every consumer at once.

```text
clients/
  ts/
    contract.ts      program ID, seeds, sizes, statuses, errors, categories
    generated.ts     generated from clients/idl — discriminators + address
    wire.ts          Borsh, PDAs, raw instruction builders, decoders, error parsing
    instructions.ts  Anchor `Program` builders (Node/tests)
    pda.ts           re-export of the wire PDA helpers
    constants.ts     re-export of contract.ts (historical entry point)
    index.ts         barrel export
  idl/               generated by `anchor build` (target/idl/asset_rental.json)
  types/             generated by `anchor build` (target/types/asset_rental.ts)
```

## Two layers, one source

- **`wire.ts`** is the raw, browser-safe layer. It imports only
  `@solana/web3.js` (no Anchor, no Node built-ins), so the portal bundles it and
  the backend runs it under Node. Discriminators come from `generated.ts`, which
  `scripts/gen-client-constants.mjs` produces from the IDL — nothing is
  hand-copied.
- **`instructions.ts`** is the Anchor `Program` layer used by the tests and
  scripts. Anchor encodes from the same IDL, so both layers describe one
  contract.

`npm run contract:check` verifies that every IDL instruction has a builder,
every IDL account has a decoder, the ID matches across Rust/Anchor/IDL/client,
and each discriminator equals `sha256("<kind>:<name>")[..8]`.

## Usage

```ts
// Browser or backend (no Anchor):
import { ixCreateRental, fetchListings, parseProgramError } from "../clients/ts/wire";

// Node scripts and the acceptance suite (Anchor builders):
import {
  PROGRAM_ID,
  RPC_URL,
  configPda,
  listingPda,
  rentalPda,
  newAssetId,
  newRentalId,
  registerAsset,
  createRental,
  settleRental,
} from "../clients/ts";
```

Every builder derives the program-owned PDAs itself, so callers never
hand-encode a seed. Nothing here reads or writes keypairs; callers supply signers
and persist IDs themselves.

## Error handling

Never read `error.message` directly from an Anchor send failure. Anchor 0.30.1 +
web3.js ≥1.95 mask it as `Unknown action 'undefined'` and discard the logs use
`parseProgramError(error)` (or `programErrorCode(error)`) from `wire.ts`. The
Anchor builders already re-simulate on failure and throw a
`ProgramInvocationError` carrying `code`, `programName`, and `logs`.

## Persist-before-submit

`newRentalId()` and `newAssetId()` return fresh 32-byte identifiers. Persist a
`rental_id` **before** submitting `create_rental`. If confirmation is uncertain,
re-read the rental PDA with the same `rental_id` — never generate a new one, or
the retry can double-charge.

## Generated artifacts

`clients/idl/`, `clients/types/`, and `clients/ts/generated.ts` come from the
program build:

```bash
bash scripts/export-clients.sh
```

Commit all three alongside any contract change. The script runs
`scripts/check-contract.mjs` and fails on any drift, including a mismatched
program ID between `declare_id!`, `Anchor.toml`, the IDL, and the client.
